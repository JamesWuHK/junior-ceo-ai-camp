# 少年CEO AI 创业营项目规则

版本：v0.1  
适用范围：课程总纲、教学过程设计、教师讲稿、Web 课件、学生端任务、作品展示、运营物料。

## 1. 课堂语言正念原则

课堂语言默认信任孩子。

面向孩子、家长和课堂大屏的文案，要从“孩子愿意欣赏、愿意观察、愿意合作、愿意表达”的正向假设出发。不要用防御式、管控式、预设问题式的话术给课堂打补丁。

心存正念：风险要在教师准备、后台审核和现场支持里处理；孩子可见的课堂表达，要保持信任、欣赏、好奇和行动感。

### 核心判断

如果一句话的底层意思是“我怕你们会做错、会冒犯、会失控”，就不要直接放到课件、大屏或学生端里。

把它改成：

- 一个正向任务。
- 一个具体观察目标。
- 一个值得期待的课堂动作。
- 一个能激发好奇心的表达。

### 推荐表达方式

| 场景 | 推荐表达 |
|---|---|
| 看未来职业照 | 带着欣赏和好奇，看一看照片里的职业线索。 |
| 看同学作品 | 找一个你想借走的好方法。 |
| 采访用户 | 像侦探一样听，先听见真实故事。 |
| 测试作品 | 观察别人怎么用，发现作品可以变得更好的地方。 |
| AI 生成结果 | 让 AI 帮忙，也带着证据做判断。 |
| 作品秀 | 看见亮点，借鉴方法，给出下一步建议。 |

### 内部审稿要拦截的表达

下面这类表达可以出现在老师内部风险判断里，但不要作为孩子可见的课件文案、学生端文案或大屏文案：

| 问题表达 | 改写方向 |
|---|---|
| 我们不评价长相，只观察线索。 | 带着欣赏和好奇，看一看照片里的职业线索。 |
| 不要嘲笑别人。 | 找一处你欣赏的画面细节。 |
| 不能只采访自己组的人。 | 让线索来自更多真实声音。 |
| 不要解释太多。 | 先看别人怎么用。 |
| 不是比赛。 | 这是互相借好方法的作品秀。 |
| 不要讲太多想法。 | 让大家看到用户怎么用、结果是什么。 |
| 这不是预知未来。 | 这是 AI 根据照片和职业关键词做出的未来想象照。 |

## 2. 课件与大屏内容边界

右侧课件区域、全屏 PPT、大屏展示和学生端，只放孩子能直接理解和参与的内容。

PPT 是老师讲课的辅助工具，不是老师讲稿本身。PPT 页面只承担视觉锚点、课堂任务、演示材料、互动入口和作品展示的作用；老师要说的话放在教师讲稿、备注或教师控制区里。

可以展示：

- 关键词和短句。
- 故事场景。
- 观察任务。
- 实验步骤。
- 示例作品。
- 学生任务。
- 作品展示。
- 互动结果。
- 二维码、倒计时、投票、任务发布等活动入口。

放在教师控制区、备注或讲稿文档中：

- 老师讲稿。
- 完整开场话术。
- 提问追问话术。
- 转场话术。
- 后台审核规则。
- 风险处理提醒。
- 隐私和授权操作细节。
- 现场支持分工。

## 3. 课程表达风格

课程面向 8-16 岁孩子，课件表达要有故事感、实验感和作品感。

### 专业名词使用原则

不要把所有专业词都替换成童趣词。只要不超出孩子理解能力，专业名词可以正常使用，并用孩子能理解的例子解释清楚。

可以正常使用并解释：

- 产品：别人真的会使用、能帮他解决问题的东西。
- 价格：别人愿意为这个产品交换什么，可能是钱，也可能是时间、推荐、星星币或一次试用机会。
- 大模型：读过很多文字和图片、能根据你的指令生成回答或内容的 AI 系统。
- 用户：真正会使用这个产品的人。
- 原型：还不是最终版本，但已经能演示核心功能的第一版产品。
- MVP / 最小可行产品：先做出最小但能验证想法的一版产品；面对低龄孩子时可以解释为“先把最重要的一个功能做出来”。

可以作为课堂比喻或活动名使用：

- 未来照相馆。
- 麻烦侦探。
- 星星币。
- 故事发布会。
- 小机关：可以用来比喻“能动起来的最小功能”，但不能替代所有“产品 / 原型 / MVP / 功能”的专业表达。

谨慎使用或放到教师内部材料：

- CEO 概念解释：对孩子不需要刻意讲定义，但可以在角色、责任和团队决策中自然出现。
- 商业模式、融资、增长：如课程环节需要，可用具体例子解释，不做成人化展开。
- 成人路演话术：保留为教师内部参考，孩子展示时用“讲清楚谁遇到什么问题，我们怎么帮助他”。

## 4. HTML 课件生成规则

本项目的教师端课件以 HTML PPT 为主，服务现场授课、大屏展示、活动发起和作品展示。课件生成工具可以使用多个 skill，但必须服从本项目的课堂规则，而不是反过来被工具风格带走。

### Skill 分工

| Skill | 项目内定位 | 适合使用 |
|---|---|---|
| `html-slides` | 主力 HTML PPT 课件生成 | 教师端右侧课件、全屏授课页、课堂互动页、任务页、作品展示页 |
| `agentic-ppt` | 儿童友好故事页和手绘感页面参考 | 未来照相馆、AI 小实验、麻烦侦探、对话气泡、手绘任务卡 |
| `guizang-ppt-skill` | 高设计感网页 PPT 参考 | 家长说明会、课程发布、结营展示中的少量视觉强化页 |
| `baoyu-slide-deck` | 可阅读分享型 slide deck | 课后家长材料、课程复盘、可导出分享的图文幻灯片 |

### 儿童课堂优先规则

- 主线永远是教学流程：故事、观察、实验、动手、作品展示。
- 一页只承载一个课堂动作，避免把讲稿、后台说明、复杂机制塞进课件页。
- 每页 PPT 优先使用标题、图像、关键词、问题、任务卡和活动按钮；不把老师完整话术写成大段文字。
- 优先做孩子能参与的页面：猜一猜、翻一翻、选一选、看一看、试一试、展示一下。
- 未来照相馆、AI 实验和用户采访环节可以使用手绘、纸张、贴纸、对话气泡等视觉语言。
- 团队空间、进度看板和作品展示页要清楚、稳定、可扫读，避免过度装饰。
- 全屏授课页必须适配投影和大屏：字号足够大，文字少，画面清楚。
- 学生端任务页必须更简单：一个任务、一个输入区、一个主按钮。

### 风格边界

- 不使用成人商务发布会风格作为儿童课堂主风格。
- 不使用大面积暗黑科技风、赛博风、金融路演风、复杂仪表盘风。
- 不用过多炫技动画影响老师控场。
- 不把工具默认模板里的成人措辞直接带进课件。
- 不把老师讲稿、审核规则、隐私处理细节写进孩子可见的 PPT 页面。

### 生成前检查

每次用 HTML PPT skill 生成课件前，先确认：

1. 当前页服务哪个教学环节？
2. 孩子在这一页要做什么动作？
3. 这页是否能全屏给孩子看？
4. 文案是否遵循“课堂语言正念原则”？
5. 页面是否支持教师从 PPT 内发起任务、互动、投屏或展示？
6. 视觉是否有趣，但没有抢走教学主线？

## 5. 内容审稿检查清单

每次新增或修改课件、讲稿、学生端文案时，至少检查这 6 个问题：

1. 这句话是否默认信任孩子？
2. 这句话是否适合直接出现在大屏或学生端？
3. 这句话是否是正向任务，而不是预防式提醒？
4. 这句话是否具体、有画面、有动作？
5. 专业名词是否被正常使用，并用孩子能理解的例子解释清楚？
6. 这句话是否让课堂更有趣、更清楚、更愿意参与？

## 6. 当前已确定的语言规则

- 未来照相馆的开场目标是热场和体验 AI 的神奇，不解释 CEO。
- 未来职业照先用故事和样例激发好奇，再让孩子提交照片和职业。
- 生成结果先回到学生端，孩子确认提交后再进入大屏展示。
- 展示未来职业照时，用欣赏和观察职业线索的语言。
- 全部职业照展示后，再说明这是 AI 的未来想象照。
- 老师的讲稿话术不直接写进大屏课件页面。
- 课件和大屏只展示孩子能直接看的内容。
