# Web教学系统国内部署方案

## 1. 结论

正式开营时，Web教学系统应部署在国内用户友好的网络环境中。默认不使用 `Vercel + Supabase` 作为生产环境。

推荐优先级：

1. **腾讯云 CloudBase 一体化路线**：适合快速做出国内可访问 MVP，开发和部署链路短。
2. **阿里云标准工程路线**：适合后续多营期、多城市、长期产品化。
3. **营地本地兜底路线**：只用于断网、备案未完成或系统异常时保障课程继续。

## 2. 不建议使用海外生产路线的原因

`Vercel + Supabase` 对早期原型很方便，但不适合作为国内开营主系统：

- 营地现场网络访问不稳定，老师端和学生端可能卡在登录、上传或展示。
- 家长端作品集访问体验不可控。
- 未来职业照、学生作品、路演照片等数据跨境和删除流程更难解释。
- 国内公开访问如果使用大陆节点，需要处理备案；如果用海外节点，速度和稳定性又不如国内云。
- 文件上传、图片展示、评分实时同步都是现场刚需，不能赌网络。

## 3. 推荐架构 A：腾讯云 CloudBase 一体化路线

### 适合情况

- 要快速做出第一版可用系统。
- 团队希望减少服务器、数据库、存储、认证的分散配置。
- 课程初期以单营期或少量营期为主。

### 架构

```text
浏览器
  教师入口 / 学生入口 / 大屏展示 / 家长展示与评分
        |
        v
CloudBase 云托管 / 云函数
        |
        +-- CloudBase 数据库或 Postgres
        +-- CloudBase 云存储 / 腾讯云 COS
        +-- 身份认证 / 团队账号
        +-- 日志与监控
        |
        v
备案域名 + CDN/EdgeOne
```

### 服务清单

| 功能 | 服务 |
|---|---|
| Web 应用 | CloudBase 云托管，部署 Next.js |
| API | CloudBase 云函数或 Next.js 服务端接口 |
| 数据 | CloudBase 数据库；复杂关系数据可接腾讯云数据库 PostgreSQL/MySQL |
| 文件 | CloudBase 云存储或 COS 私有 Bucket |
| 登录 | CloudBase 身份认证；课堂上建议团队账号 |
| 加速 | 腾讯云 CDN 或 EdgeOne |
| 域名 | 已备案域名 |

### 优点

- 国内访问友好。
- 开发和部署链路短。
- 数据库、存储、函数、托管在同一生态里。
- 适合快速把原型变成可用系统。

### 风险

- 数据模型复杂后，要提前规划关系型数据库。
- 如果后续要迁移到标准云架构，需要预留数据导出和接口边界。

## 4. 推荐架构 B：阿里云标准工程路线

### 适合情况

- 希望系统长期产品化。
- 未来会有多城市、多营期、多角色后台。
- 需要更标准的关系型数据库、对象存储和运维监控。

### 架构

```text
浏览器
  教师入口 / 学生入口 / 大屏展示 / 家长展示与评分
        |
        v
阿里云 SAE / ECS / 轻量应用服务器
        |
        +-- RDS PostgreSQL / MySQL
        +-- OSS 私有 Bucket
        +-- 日志服务 / 监控
        |
        v
备案域名 + CDN
```

### 服务清单

| 功能 | 服务 |
|---|---|
| Web 应用 | SAE 部署 Next.js Docker/Node 服务，或 ECS 自管 |
| API | Next.js Route Handlers / Server Actions / Node 服务 |
| 数据 | RDS PostgreSQL 或 MySQL |
| 文件 | OSS 私有 Bucket + 服务端签名上传/下载 |
| 登录 | 自建 Session/短码登录/团队账号 |
| 加速 | 阿里云 CDN |
| 域名 | 已备案域名 |

### 优点

- 架构通用，长期可维护。
- 数据库、对象存储、日志和监控能力成熟。
- 适合以后做正式 SaaS 化管理后台。

### 风险

- 初期配置和运维工作比一体化平台多。
- 需要开发团队具备基础云运维能力。

## 5. 营地本地兜底路线

正式系统即使部署在国内云，也必须准备本地兜底。

### 兜底材料

- 离线 HTML 课件。
- 纸质任务卡。
- 本地 MVP 演示模板。
- 本地作品文件夹。
- 纸质评分表。
- 老师电脑上的作品展示页。

### 本地流程

```text
系统异常
  -> 老师切离线课件
  -> 学生用纸质任务卡继续
  -> MVP 和作品截图保存到本地文件夹
  -> 路演用本地作品墙展示
  -> 课后由助教补录到线上系统
```

兜底路线不是降级课程质量，而是保证课堂节奏不被网络绑架。

## 6. 备案和域名策略

### 正式开营

- 使用机构主体下的已备案域名。
- 域名解析到国内云资源。
- 课前至少 7 天完成全流程测试。

### 试点阶段

如果备案尚未完成，可以选择：

- 使用机构已有备案域名的二级域名。
- 使用营地局域网本地部署。
- 使用云厂商临时测试环境做内部评审。

不建议：

- 正式开营当天使用未备案大陆域名。
- 让家长访问无备案、访问慢、不可控的海外链接。
- 把学生照片和作品放到公开图床。

## 7. 数据与文件存储原则

### 数据

- 学生个人信息尽量少采集。
- 学生真实姓名可在运营后台保存，但展示页使用昵称或团队名。
- 团队账号优先，减少儿童个人账号。
- 教师入口账号按主讲、现场支持、评委/观察员分角色授权。

### 文件

- 儿童照片、未来职业照、路演照片默认放私有存储。
- 展示页只引用审核后的成品图。
- 原始照片和成品图分目录保存。
- 支持按授权删除原始照片。
- 不使用公开 Bucket 存储未成年人照片。

### AI

- AI 接口由服务端调用。
- 学生端不直接接触 API Key。
- Prompt 模板内禁止真实姓名、学校、手机号、住址、身份证。
- 生图前检查授权状态。

## 8. 现场网络验收

开营前必须在真实营地网络验证：

| 项目 | 标准 |
|---|---|
| 老师端 | 大屏连续切换课件不卡顿 |
| 学生端 | 30 人同时打开和提交任务可用 |
| 文件上传 | 10 组同时上传图片/截图成功 |
| 作品展厅 | 大屏路演模式切换顺畅 |
| 评分中心 | 5-8 名评委同时提交评分成功 |
| 家长端 | 手机浏览审核后作品页可用 |
| 断网兜底 | 5 分钟内切到离线流程 |

## 9. 推荐开发顺序

1. 先用静态原型确认教师端、学生端、作品展厅和评分中心的页面动线。
2. 选择腾讯云 CloudBase 或阿里云路线。
3. 完成单营期数据模型和团队账号。
4. 完成教师发布任务、学生提交和教师入口进度看板。
5. 完成作品上传、审核和展厅。
6. 完成评分中心和奖项建议。
7. 接入备案域名和国内 CDN。
8. 做现场网络压测和断网演练。

## 10. 当前建议

如果目标是在近期把系统跑进真实营期，建议先走：

```text
Next.js
  + 腾讯云 CloudBase 云托管
  + CloudBase 数据库，复杂关系数据可接腾讯云数据库
  + COS 或 CloudBase 云存储
  + 已备案域名
  + 团队账号/短码登录
```

等课程跑过 1-2 期后，再根据数据复杂度决定是否迁移到更标准的阿里云或腾讯云数据库 + 对象存储 + 自管服务架构。
