# Web教学系统 MVP 技术选型与开发路线

## 1. 技术选型结论

面向国内学生、家长和营地现场网络，正式系统默认采用国内友好的部署路线。`Vercel + Supabase` 只保留为海外快速验证参考，不作为开营生产环境。

### 国内生产推荐路线

| 层 | 推荐 | 理由 |
|---|---|---|
| 前端/全栈框架 | Next.js App Router | 适合做课件页、教师入口、学生入口、大屏展示和服务端接口；框架本身不绑定海外平台 |
| 应用运行环境 | 腾讯云 CloudBase 云托管/云函数，或阿里云 SAE/ECS | 国内访问更稳定；可接入备案域名；便于统一运维 |
| 数据库 | CloudBase 数据库用于快速 MVP；复杂关系数据使用腾讯云/阿里云托管 PostgreSQL/MySQL | 存营期、学生、团队、任务、提交、评分等结构化数据；数据留在国内云环境 |
| 登录与权限 | 团队账号 + 教师入口实名账号 + 服务端权限校验 | 不让孩子注册不可控个人账号；现场支持人员按权限进入教师入口 |
| 文件存储 | 腾讯云 COS 或阿里云 OSS | 存未来职业照成品、海报、截图、录屏；支持私有存储、权限策略和 CDN |
| CDN/加速 | 腾讯云 CDN/EdgeOne 或阿里云 CDN | 课件静态资源、作品图片和展示页国内访问更快 |
| 域名与备案 | 中国大陆节点需完成 ICP 备案，按云厂商备案流程办理 | 面向国内公开访问必须提前处理，避免开营时域名不可用 |
| 课堂实时同步 | WebSocket、SSE、轮询，或云开发实时能力 | 教师发布任务、提交状态、评分汇总需要接近实时 |
| AI 能力 | 服务端调用国内可访问模型/工具 | API Key 只放服务端；学生端只访问教学系统 |
| 语音识别 | 国内可访问的 ASR 服务，或云厂商语音识别能力 | 支持孩子用语音说理想职业，系统转文字并提取职业关键词 |

### 两条可落地方案

#### 方案 A：腾讯云 CloudBase 一体化路线

适合：最快做出国内可访问 MVP，团队不想一开始维护太多云组件。

| 层 | 推荐 | 理由 |
|---|---|---|
| 应用 | Next.js 前端 + CloudBase 云托管/云函数 |
| 数据 | CloudBase 数据库；复杂关系数据可接腾讯云数据库 PostgreSQL/MySQL |
| 认证 | CloudBase 身份认证，课堂上仍建议以团队账号为主 |
| 文件 | CloudBase 云存储或腾讯云 COS |
| 展示 | 静态托管/云托管 + 国内域名 + 备案 |
| 优点 | 后端、数据库、存储、认证、托管在同一生态内，开发和部署快 |
| 风险 | 如果后期做复杂关系报表，需要提前规划数据库模型 |

#### 方案 B：阿里云标准工程路线

适合：希望数据库、对象存储、部署和监控更工程化，后续可扩展多营期/多城市。

| 层 | 推荐 |
|---|---|
| 应用 | Next.js Docker/Node 服务部署到 SAE，或 ECS/轻量应用服务器 |
| 数据 | RDS PostgreSQL 或 MySQL |
| 文件 | OSS 私有 Bucket + 服务端签名上传/下载 |
| 加速 | CDN 加速静态课件、作品图片和展示页 |
| 权限 | Next.js 服务端 Session + 数据库权限模型 |
| 优点 | 架构通用、可控性高、适合长期产品化 |
| 风险 | 初期运维和配置工作比一体化平台更多 |

#### 方案 C：营地本地兜底路线

适合：现场网络不稳定或备案尚未完成时的应急上课。

| 层 | 推荐 |
|---|---|
| 课件 | 离线 HTML 课件和静态原型 |
| 数据 | 每组本地文件夹 + 纸质任务卡 |
| 展示 | 老师电脑本地作品墙 |
| 补录 | 课后由现场支持人员把关键提交补进线上系统 |

这不是正式产品路线，只是保障课堂不中断。

#### 海外快速验证参考

`Vercel + Supabase` 可以用于早期原型、海外用户验证或内部演示，但不建议作为国内开营生产环境，原因是现场网络、访问稳定性、文件上传、家长展示和数据合规都更难控。

官方依据：

- Next.js 官方文档将 Next.js 定义为用于构建全栈 Web 应用的 React 框架，适合用组件构建 UI 并处理应用功能。
- 阿里云备案文档说明，在中华人民共和国境内提供非经营性互联网信息服务应办理备案，未备案不得在境内从事非经营性互联网信息服务。
- 腾讯云备案文档同样说明，非经营性互联网信息服务实行备案制度，未履行备案手续不得从事互联网信息服务。
- CloudBase 官方文档说明其内置数据库、存储、身份认证、云函数与云托管等能力，适合快速构建 Web 应用、管理后台和 AI 应用。
- 阿里云 SAE 官方文档说明其支持通过代码包或镜像部署应用，不限制技术栈语言，并提供弹性伸缩和日志监控等能力。
- 阿里云 OSS 和腾讯云 COS 都是对象存储服务，适合承载图片、截图、录屏等文件资产。

## 2. 为什么不用纯静态网站

纯静态网站可以做课件和展示，但不适合完整营期系统：

- 无法可靠保存学生任务提交。
- 无法控制学生、老师、家长权限。
- 无法安全处理照片授权和作品审核。
- 无法实时汇总各组进度和评分。

因此静态 HTML 只适合作为：

- 早期交互原型。
- 断网本地兜底。
- 课件离线备份。

## 3. 为什么不用复杂 LMS

传统 LMS 的问题是太重：

- 课堂流程不够灵活。
- 对 8-16 岁学生界面太复杂。
- 很难承载“未来职业照、烦人墙、MVP、路演评分”这类强活动型流程。

本课程更适合定制轻量系统：围绕 3 天 PBL 流程做深，而不是做泛课程平台。

## 4. MVP 功能范围

### 必做

| 模块 | MVP 功能 |
|---|---|
| 营期管理 | 创建营期、学生名单、分组 |
| 权限 | 教师入口、学生入口、评委/家长观察权限 |
| HTML PPT 授课台 | 课程时间线、HTML 课件页、PPT 内活动发起、任务发布、倒计时 |
| 学生任务 | 当前任务表单、团队任务提交、个人反思 |
| 团队空间 | 项目资料、MVP 链接、截图、测试反馈、路演稿 |
| 互动 | 烦人墙、投票、卡点墙、同伴反馈 |
| 作品展厅 | 团队作品页、审核发布、路演模式 |
| 评分 | 评委评分、同伴投票、奖项建议 |
| 安全 | 照片授权记录、内容审核、原始照片删除标记 |
| 语音采集 | 扫码录音、语音转文字、职业关键词提取、语音原文件删除 |

### 可延后

| 模块 | 延后原因 |
|---|---|
| 多校区复杂管理 | 第一版先服务单营期 |
| 家长长期账号 | 结营展示可先用受控链接 |
| 视频直播 | 非核心 |
| 复杂 AI 生成器 | 先由老师或现场支持人员统一操作 |
| 支付和报名 | 不是教学系统核心 |
| 长期学习档案 | 等课程跑通后再做 |

## 6. 权限规则

| 角色 | 可以看 | 可以写 | 不可以 |
|---|---|---|---|
| 学生 | 自己任务、本团队资料、已公开作品 | 自己任务、本团队任务、同伴反馈 | 看其他队未公开资料、看评分明细 |
| 老师 | 全部营期数据 | 课件、任务、批注、审核、评分 | 暴露 API Key 到前端 |
| 现场支持 | 所负责营期数据 | 批注、卡点、审核辅助 | 修改核心评分规则 |
| 家长/评委 | 已审核作品和评分表 | 路演评分/留言 | 看未审核照片、原始学生资料 |

关键规则：

- 所有学生表、提交表、作品表必须有服务端权限校验；如果数据库支持行级安全，可叠加使用。
- 学生只能访问自己和本团队数据。
- 展示页只读已审核内容。
- 服务端密钥只能在后端使用。
- 照片原图和展示成品分开存储，原图默认课后删除。
- 语音原文件和识别文本分开存储，原音频默认活动后删除。
- 对象存储默认私有 Bucket，不使用公开读写 Bucket 存儿童照片。
- 家长展示页使用受控链接、短码或登录访问，不把作品页作为全网公开相册。

## 6.1 国内部署注意事项

### 备案与域名

- 如果系统部署在中国大陆节点并使用域名公开访问，应提前办理 ICP 备案。
- 备案通常需要域名、主体信息、云资源和网站信息，不能等到开营前一天才处理。
- 未完成备案前，不建议把正式课堂系统部署在大陆公开域名上；可用本地局域网、临时测试环境或已备案域名先跑试点。

### 未成年人数据

- 未来职业照、学生作品、路演照片、导师反馈都属于敏感度较高的课程数据。
- 14 周岁以下儿童个人信息应取得监护人同意，并按最小必要原则处理。
- 原始照片、成品照、作品展示页要分开授权：允许生成，不等于允许公开展示；允许课堂展示，不等于允许课后长期保存。

### AI 接口

- AI Key 只放服务端。
- 学生端提交给 AI 的内容要经过系统模板限制，避免上传真实姓名、学校、手机号、住址、身份证等信息。
- 生图工具如果调用第三方平台，必须提前确认图片上传、保存和删除规则。
- 语音识别工具如果调用第三方平台，必须提前确认音频上传、保存和删除规则。

### 现场网络

- 开营前至少在营地网络测试一次，而不是只在办公室测试。
- 同时模拟 30 人访问、10 组文件上传、评委评分和大屏展示。
- 大屏电脑、老师电脑、现场支持电脑、学生电脑应使用同一个正式访问域名测试。

## 7. 开发节奏

### Sprint 0：静态原型

目标：确认信息架构和课堂动线。

产出：

- HTML PPT 授课台静态页。
- 学生任务静态页。
- 团队作品墙静态页。
- 路演评分静态页。

### Sprint 1：可跑通单营期

目标：一个真实班级能用系统完成 3 天流程。

产出：

- 国内部署环境。
- 团队账号和教师入口账号，按主讲、现场支持等角色授权。
- 创建营期和分组。
- 课件展示。
- 当前任务提交。
- 团队空间。
- 简单作品展厅。

### Sprint 2：课堂实时与教师入口进度看板

目标：提升现场控场能力。

产出：

- 教师发布当前任务。
- 学生提交状态实时更新。
- 卡点墙。
- 教师入口进度看板。
- 大屏展示模式。

### Sprint 3：最终展示和评分

目标：支撑 Day 3 路演和课后家长展示。

产出：

- 作品审核。
- 路演顺序。
- 评委评分。
- 奖项建议。
- 家长展示链接。

### Sprint 4：照片授权和内容安全增强

目标：把未成年人照片和作品安全流程做稳。

产出：

- 授权状态管理。
- 原图删除记录。
- 展示图审核。
- 敏感信息检查。
- 操作日志。

### Sprint 5：国内生产环境加固

目标：让系统在国内营地现场稳定可用。

产出：

- ICP 备案域名接入。
- 国内 CDN 加速。
- 对象存储私有化和签名链接。
- 数据备份与恢复。
- 访问日志与错误监控。
- 营地网络压测报告。

## 8. 现场部署建议

### 标准方式

- 系统部署在国内云线上环境。
- 使用已备案域名访问。
- 老师、现场支持人员和学生都通过浏览器访问；现场支持人员使用教师入口权限。
- 每组至少一台电脑登录团队账号。
- 大屏使用教师端展示。
- 课件静态资源和作品图片走国内对象存储/CDN。

### 试点方式

在备案或正式域名未完成前，可先用：

- 已备案的公司/机构测试域名。
- 云厂商临时测试域名，仅限内部评审，不用于正式家长访问。
- 营地局域网本地部署。

试点方式不得替代正式生产方案。

### 离线兜底

必须准备：

- 离线 HTML 课件。
- 纸质任务卡。
- 本地 MVP 演示模板。
- 纸质评分表。
- 作品截图/录屏本地备份。

### 现场账号建议

- 不建议让孩子注册个人账号。
- 每组使用一个团队账号。
- 老师和现场支持人员使用实名工作账号，统一进入教师入口。
- 评委使用一次性评分链接或短码。

## 9. 验收清单

正式开营前至少验证：

| 检查项 | 通过标准 |
|---|---|
| 国内域名 | 正式域名已备案或使用合规试点访问方式 |
| 国内访问速度 | 营地网络下老师端、学生端、家长端均可稳定打开 |
| 大屏课件 | 所有模块可切换，字体清楚 |
| 学生提交 | 每张任务卡都能保存 |
| 团队空间 | 能看到产品资料、MVP 链接、反馈 |
| 投票互动 | 30 人同时投票不卡顿 |
| 文件上传 | 10 组同时上传图片/截图能上传、审核、展示 |
| 对象存储权限 | 儿童照片和作品文件不是公开 Bucket 裸露访问 |
| 权限 | 学生看不到未公开数据 |
| 照片授权 | 未授权学生不会进入照片生成流程 |
| 数据删除 | 原始照片可按授权规则删除，并有操作记录 |
| 展示页 | Day 3 能按路演顺序展示 |
| 家长端访问 | 家长使用受控链接或短码能查看审核后作品 |
| 评分 | 评委能提交，老师能汇总 |
| 断网兜底 | 纸质和离线文件能继续上课 |

## 10. 当前静态原型的边界

`少年CEO_Web教学系统原型.html` 只用于演示：

- 页面信息架构。
- 教师端/学生端/作品展厅/评分中心的关系。
- 任务和团队空间如何承接课程。

它不具备：

- 真登录。
- 真文件上传。
- 多设备同步。
- 服务端存储。
- 权限隔离。

正式开发时不能直接把静态原型当生产系统使用。
