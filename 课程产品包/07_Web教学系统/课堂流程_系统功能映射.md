# 课堂流程与 Web 系统功能映射

## 1. 使用原则

整个营期默认以 Web 系统作为课堂主界面：

- 老师不再单独打开传统 PPT，而是用“HTML PPT 授课台”展示课件，并在当前课件页里直接发起扫码、投票、任务提交、照片墙和评分等活动。
- 学生不再只填写纸质任务卡，而是在“学生工作台”里提交关键任务。
- 现场支持人员不再靠口头问进度，而是在教师入口的“进度看板”里看每组状态。
- Day 3 不再临时拼 PPT，而是在“作品展厅”里呈现最终成果。

纸质物料仍然保留，但定位变为：

- 断网兜底。
- 低龄学生草稿。
- 现场贴墙和仪式感。

## 5. 大屏模式

大屏只显示当前最需要全班共同看的内容：

- HTML PPT 当前课件页，以及本页正在发起的课堂活动状态。
- 任务倒计时。
- 需求线索墙/投票结果。
- 未来职业照大屏墙。
- 团队进度排行。
- 作品展厅。
- 作品秀评分结果。

大屏不显示：

- 未审核的学生照片。
- 学生真实手机号、学校、住址。
- 未公开的个人反思。
- 原始评分明细中的敏感评语。

## 6. 官网入口与学生端默认页面

官网入口：

- 教师入口：老师从 `camps.wanli.wiki` 的教师入口进入课程目录、课件演示、活动发起和后台管理。
- 学生入口：孩子从官网学生入口或课堂二维码进入当前任务页，只看到本节课要做的事。

学生登录后只看到四个入口：

- 当前任务。
- 我的团队。
- 我们的作品。
- 给别人反馈。

不要让学生端出现复杂后台、课程管理、全量资料库。学生端越简单，课堂越稳。

PPT 和大屏页面只展示孩子能直接看的内容；老师讲稿、后台状态、审核规则和控场提醒不放进全屏演示画面。

## 7. 教师入口内的支持区

现场支持人员在教师入口内看到：

- 全班 6 组进度。
- 每组当前卡点。
- 未提交任务提醒。
- 需要审核的照片/作品。
- 小机关链接是否可打开。

支持区的核心不是“看资料”，而是“知道下一分钟该去帮哪一组”。

## 8. 纸质物料与系统的关系

| 物料 | 系统内对应 | 使用方式 |
|---|---|---|
| 未来照相馆任务卡 | 扫码采集页：照片上传 + 职业点选/语音录入 + 提交 | 系统采集为主，纸质卡只用于未带设备或语音识别失败时兜底 |
| 需求线索便利贴 | 需求线索互动区 | 现场贴墙制造气氛，系统负责投票排序 |
| 用户采访卡 | 采访记录表单 | 采访时可纸笔，回座后录入系统 |
| 小机关功能卡 | 小机关功能表单 | 系统提交后老师审核 |
| 故事发布五步卡 | 故事发布稿编辑器 | 纸质卡用于彩排，系统保存终稿 |
| 评分表 | 评分中心 | 纸质表作为断网备用 |

## 9. 系统失败时的课堂兜底

| 失败场景 | 兜底方式 |
|---|---|
| 系统打不开 | 老师用离线课件，学生用纸质任务卡 |
| 学生端无法登录 | 每组选一个公共设备提交 |
| 文件上传失败 | 先截图/录屏保存到本地，课间由现场支持人员补传 |
| 大屏异常 | 老师电脑本地打开课件和作品 |
| 评分系统异常 | 使用纸质评分表，课后录入 |

系统是课堂增益，不应成为课堂唯一生命线。关键活动都必须保留离线兜底。
