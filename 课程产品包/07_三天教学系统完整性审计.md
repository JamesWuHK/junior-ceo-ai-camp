# 三天教学系统完整性审计

日期：2026-06-13
受众层级：教师 / 课程设计 / 系统实现。本文不是孩子可见 PPT。

## 1. 审计目标

本轮审计围绕一个目标：教学系统要完整支持 3 天 PBL 创业营，并且以 HTML 课件为核心。

具体要求拆成 6 条：

1. D1 / D2 / D3 的教学环节在教师端主线中完整出现。
2. 除“未来照相馆”这个开场体验外，后续知识输入和项目推进都能进入统一 HTML 课件。
3. 四个案例从 Day 1 讲到 Day 3：AI 知识、创业知识、产品原型、试玩迭代、作品发布都反复使用同一批案例。
4. 知识输入采用“故事 / Demo 或案例 / 实验”结构。
5. 孩子学完一段知识后，马上进入团队实践，实践结果能被系统保存。
6. 孩子可见层不混入后台、技术、运营和教师内部话术。

## 2. 固定四案例

| 赛道 | 案例 | 需求 | 第一版产品 | 贯穿作用 |
|---|---|---|---|---|
| 生活帮手 | 上学出门检查台 | 课表、作业和老师通知分散在不同地方，早上出门怕漏带 | 今天必带 / 要提前确认 / 到校先做三栏出门清单 | 讲“AI 整理分散信息，帮孩子自查” |
| 学习工具 | 应用题拆题板 | 长应用题里人物、数字和问题混在一起，不知道先看哪句 | 谁、已知、要求、第一步提示 | 讲“提示词要清楚”和“AI 不直接给答案” |
| 创意工坊 | 四格漫画分镜台 | 有故事点子，却不知道四格顺序怎么排 | 4 格分镜和对白草稿 | 讲“AI 出草稿，人继续改” |
| 校园社区 | 校园活动组队板 | 想参加或发起活动，却找不到同伴一起报名 | 活动卡、报名问题和人数进度 | 讲“校园社区价值来自连接真实同伴” |

- 未调用的 sketchnote 图片课件路径已从前端删除，当前主课件只保留正式四案例 HTML 入口。
- 教师端赛道建议已对齐官网四条赛道；正式样本项目改为上学出门检查台、应用题拆题板、四格漫画分镜台、校园活动组队板。
- 四案例 HTML 课件已修复 URL 跳转：`?module=...` 不再被缺失的 `slide` 参数误判为第 0 页。
- 插入 `2 分钟 Demo` 页后，AI 原理、Day 2 回看、技术路线等后续页码已同步顺延。
- 按官网四条赛道新增 4 个完整案例页：生活帮手、学习工具、创意工坊、校园社区各自独立成页，不再一页带过。
- Day 2 开场 `今天必须做出来` 已改为可发布任务，学生端会保存为核心动作卡，避免只停留在口头讨论。
- 学生端 `我的团队` 已增加本组最新材料，`我们的作品` 已纳入核心动作、路线、作品入口和迭代清单，孩子能看到自己刚提交的团队成果。
- 教师端进度看板的最近进展已补充材料标题和关键内容，老师巡场时能直接看到每组交了什么。
- 四个样本项目已按官网赛道重新梳理为：上学出门检查台、应用题拆题板、四格漫画分镜台、校园活动组队板；生活帮手、学习工具、创意工坊、校园社区四条赛道都能完整讲需求、产品、AI 帮忙和价值。
- 四案例 HTML 课件已改成单页演示模式，只显示当前 active slide，避免 iframe 或截图时落到页面下半截。
- 四案例 HTML 课件已补强视觉锚点：24 页都有标准标题，每页增加一个淡色贴纸式符号，降低“全都长一样”的感觉。
- 核心 HTML 课件已把工具名放进对应使用场景：豆包、DeepSeek、扣子、秒搭、WorkBuddy、多模态，不再只停留在设计文档里。
- 学生端表单占位文字已清理早期试探案例，统一换成上学出门检查、应用题拆题、四格漫画分镜和校园活动组队这四个正式案例语境。

## 7. 当前结论

当前系统已经形成一条可继续打磨的主线：

> 未来照相馆开场 → AI 基本原理 → 四案例创业知识 → 团队定方向 → AI 任务单 → MVP → 工具路线 → V1 制作 → 互测迭代 → 价值与包装 → 发布材料 → 作品秀与反思

下一步应继续做人工视觉审稿：逐页判断孩子是否一眼看懂、画面是否足够有趣、每页是否只承担一个课堂动作。
