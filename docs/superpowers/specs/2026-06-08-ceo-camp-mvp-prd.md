# 少年CEO AI 创业营 Web 系统开营 MVP PRD

日期：2026-06-08  
状态：草案  
范围：`camps.wanli.wiki` 课堂系统、教师端、学生端、大屏、未来照相馆、作品展示

## 1. 产品定义

少年CEO AI 创业营 Web 系统不是普通官网、LMS 或单一作品墙，而是三天 AI PBL 创业营的课堂操作系统。

它要解决的核心问题是：

- 老师按 D1 / D2 / D3 教学时间线推进课堂。
- 孩子只看到当前要做的一件任务，并能提交作品。
- 大屏展示课堂里的即时成果。
- 家长最终能看到孩子做出了什么，而不是只看到课程口号。
- 儿童照片、语音和生成图经过授权与老师确认后才进入展示区。

一句话定位：

> 老师用它带课，孩子用它完成任务，作品通过它被看见。

## 2. 现状快照

当前系统已经具备一个可运行 MVP 骨架，最完整的产品切片是“未来照相馆”。

已具备：

- 生产入口：`https://camps.wanli.wiki`
- API 入口：`https://api.camps.wanli.wiki`
- 教师端：`/teacher`
- 学生端：`/student`
- 大屏端：`/wall`
- 教师登录与学生登录。
- D1 / D2 / D3 课程结构与课件展示骨架。
- 教师端发布当前任务、进入全屏授课、打开大屏。
- 学生端当前任务展示。
- 未来照相馆扫码拍照上传。
- 手机拍照页免登录，通过二维码里的学生身份匹配。
- 学生填写理想职业并提交。
- 后端支持照片上传、COS 上传、未来照相馆提交、生成任务、老师确认、大屏展示。
- 大屏支持展示已确认的未来照相馆结果。

部分具备但还未产品化：

- 小组、任务提交、作品展厅、奖项、发布记录等数据结构已经存在，但 UI 和课堂流程没有完全串起来。
- 教师端已经有课程时间线，但仍需要把所有关键环节变成稳定的“课件 + 任务 + 展示”闭环。
- 官网已有家长宣传内容，但课堂系统需要继续补齐可兑现的作品产出。

当前主要技术风险：

- 前端核心逻辑集中在单个大文件中，后续迭代容易互相影响。
- 生产部署已经可用，但部署、CDN 刷新、健康检查还需要沉淀成更稳定的流程。
- “未来照相馆”已经跑通，但手机浏览器、微信环境、上传失败、扫码错配等异常场景还需要继续压实。

## 3. 产品原则

### 3.1 课堂时间线优先

教师端首页和主操作路径必须围绕 D1 / D2 / D3 展开。

功能为课程服务，不把课件、任务、大屏、学员、作品等做成一排平铺工具。

### 3.2 孩子当前任务优先

学生端只展示当前任务。

孩子不需要看到教师课件、后台状态、技术说明、调试信息、接口状态或复杂导航。

### 3.3 作品最终可见

每个核心教学环节都要留下一个可展示或可复盘的产出。

未来照相馆产出是未来职业照；后续 PBL 环节产出应包括问题卡、用户反馈、产品一句话、原型链接、路演卡片等。

### 3.4 内部控制不上屏

孩子可见区域包括：

- 教师端右侧课件画布。
- 全屏演示。
- 学生端当前任务。
- 学生提交成功提示。
- 大屏照片墙。
- 官网公开展示给孩子和家长看的作品区。

这些区域不能出现内部管理语言，例如：

- 后台
- 审核
- 待审核
- 管理配置
- 生成队列
- 发布状态
- 接口
- API
- 权限
- 数据库
- 同步
- 日志
- 运营

这些内容如果必须出现，只能进入教师控制区、后台管理、技术文档或教案备注。

## 4. 角色与边界

### 4.1 教师

教师是课堂推进者。

教师端需要支持：

- 查看三天课程时间线。
- 打开当前模块课件。
- 全屏授课。
- 发布学生任务。
- 查看学生完成情况。
- 管理学员和小组。
- 控制大屏内容。
- 确认哪些作品可以展示。
- 管理最终作品展。

教师端可以出现内部状态和管理语言，但这些内容不能复制到孩子可见课件和大屏。

### 4.2 学生

学生是任务完成者。

学生端只需要支持：

- 登录或通过课堂二维码进入指定任务。
- 查看当前任务。
- 上传照片、文字、选择、语音或产品链接。
- 查看自己的提交结果。
- 在需要时确认提交。

学生端不提供课程后台、课件目录、调试入口或教师控制功能。

### 4.3 大屏

大屏是课堂共同观看区域。

大屏只展示：

- 名字占位。
- 已确认可展示的照片或作品。
- 活动结果。
- 小组项目卡片。
- 路演和作品秀内容。

大屏不展示：

- 内部处理状态。
- 技术错误。
- 后台说明。
- 授权流程。
- 老师控场提醒。

### 4.4 家长

家长是成果观察者。

家长不需要看到课堂后台，只需要看到：

- 孩子经历了哪些环节。
- 每组做了什么项目。
- 作品能不能打开体验。
- 孩子在项目里承担了什么。
- 最终展示和奖项结果。

## 5. 开营 MVP 范围

### 5.1 P0：必须稳定

P0 是开营现场必须可用的范围。

#### P0-1 教师端可进入

需求：

- 教师可以通过教师入口登录。
- 登录后默认进入三天课程总控。
- 教师可以切换 D1 / D2 / D3。
- 教师可以打开当前模块课件。
- 教师可以进入全屏授课。

验收：

- 生产环境教师端可访问。
- 登录失败有清晰提示。
- 登录成功后不出现调试信息。
- 全屏课件内容属于孩子可见层，不混入内部语言。

#### P0-2 学生端可进入

需求：

- 学生可以通过学生入口登录。
- 学生登录后只看到当前任务。
- 学生端不展示教师端、后台、调试信息或 API 地址。

验收：

- 生产环境学生端可访问。
- 学生账号能进入。
- 账号错误有清晰提示。
- 当前任务文案短、直接、可执行。

#### P0-3 未来照相馆闭环

需求：

- 教师端课件按固定叙事顺序推进：
  1. 讲一个神奇照相馆的故事。
  2. 展示“现在的孩子 + 长大后的职业照”样片。
  3. 让孩子扫码进入学生端。
  4. 孩子拍一张自己的照片。
  5. 孩子说出或选择自己的理想职业。
  6. 生成结果先回到学生端。
  7. 孩子确认提交后进入展示流程。
  8. 全班照片墙亮起来后再解密 AI。
  9. 最后引出大模型、提示词、图像生成。
- 学生端任务固定为：
  - 上传照片。
  - 回答：`你理想的未来职业是：`
  - 可以选择职业，也可以语音录入。
  - 主按钮为：`提交`。
- 手机扫码拍照不需要再次登录。
- 二维码中携带学生身份。
- 后端校验二维码身份，避免错配。
- PC 学生端能看到手机上传的照片预览。
- 老师确认后，大屏才展示结果。

验收：

- 每个学生二维码只匹配该学生。
- 手机端可打开相机或相册。
- 上传成功后 PC 学生端能刷新出照片。
- 学生可以填写或说出理想职业。
- 提交后有孩子能理解的成功反馈。
- 大屏只展示可展示的结果，不展示内部处理词。

#### P0-4 大屏照片墙

需求：

- 大屏先显示学生名字占位。
- 学生提交后，教师端可以处理展示结果。
- 展示结果进入照片墙。
- 每张照片可以点开放大浏览。
- 多张样片或作品可以切换浏览。

验收：

- 大屏可在生产环境打开。
- 照片墙适合投影观看。
- 图片不是窄条裁切，能看清主体。
- 点开后可以查看完整图片。
- 大屏不出现内部处理语言。

#### P0-5 隐私与展示边界

需求：

- 儿童原始照片默认按私有素材处理。
- 未经老师确认的素材不进入大屏。
- 未经授权的素材不进入公开展示。
- 前端不写入任何密钥。

验收：

- 学生上传路径不暴露密钥。
- 大屏只取展示结果。
- 官网公开展示不直接展示原始儿童照片。

### 5.2 P1：三天课程主线成立

P1 是让系统真正成为三天营课堂操作系统的范围。

#### P1-1 D1 问题发现

需求：

- 教师可以发布“发现一个真实问题”的任务。
- 学生可以提交生活中的问题。
- 小组可以选择一个问题继续推进。
- 教师端可以把问题卡投到大屏。

建议产出：

- 问题卡。
- 用户是谁。
- 遇到的麻烦是什么。
- 现在怎么解决。

#### P1-2 D1 用户观察

需求：

- 学生或小组可以记录采访对象和一句真实反馈。
- 教师端可以查看每组收集了多少条反馈。
- 大屏可以展示精选反馈。

建议产出：

- 用户声音卡。
- 关键发现。

#### P1-3 D2 产品定义

需求：

- 每组填写产品一句话：
  - 为谁。
  - 解决什么问题。
  - 用什么方式解决。
- 每组可以生成产品卡片。
- 教师可以在大屏展示产品卡片。

建议产出：

- 产品名称。
- 目标用户。
- 核心问题。
- 产品一句话。

#### P1-4 D2 原型链接展示

需求：

- 系统不限制产品形态。
- 网页、聊天机器人、故事生成器只是例子。
- 多数产品应以浏览器可体验为主。
- 每组可以提交一个产品链接。
- 系统用卡片形式集成到展示区。
- 卡片点击后跳转到对应产品。
- 如果产品部署到自有服务器，应能填写自有链接。

验收：

- 每组至少有一个可点击产品卡片。
- 卡片包含产品名、团队、解决的问题、产品链接。
- 点击卡片能打开产品体验页。
- 大屏展示时适合现场浏览和路演。

#### P1-5 D2 同伴试用反馈

需求：

- 其他组可以打开产品链接体验。
- 学生可以提交一句反馈。
- 教师端可以看到反馈汇总。
- 小组可以根据反馈修改产品介绍或原型。

建议产出：

- 我试用了什么。
- 我觉得最有用的地方。
- 我建议改进的地方。

#### P1-6 D3 路演与作品展

需求：

- 每组生成最终展示卡片。
- 教师可以选择展示顺序。
- 大屏可以逐组展示。
- 家长可见页面可以展示最终作品。

建议产出：

- 产品名称。
- 团队成员。
- 目标用户。
- 解决的问题。
- 产品链接。
- 展示图。
- 一句话价值。

### 5.3 P2：结营展示增强

P2 是家长展示和课程品牌沉淀。

需求：

- 每期营有作品合集页。
- 每组有独立项目页。
- 老师可以选择哪些作品公开。
- 支持奖项、点评和证书内容。
- 支持按期数归档。

验收：

- 家长打开链接能看到真实作品。
- 每个作品都有可理解的项目说明。
- 可公开内容不包含未授权儿童照片或原始素材。

## 6. 页面需求

### 6.1 教师端首页

主线：

- D1 / D2 / D3。
- 每天模块。
- 当前模块课件。
- 当前模块可发起活动。
- 学生完成情况。

不建议：

- 首屏堆满并列功能入口。
- 把后台管理、调试、官网入口配置放到课堂主线中。

### 6.2 教师端课件区

需要：

- 页码切换。
- 全屏授课。
- 当前页发布任务。
- 当前页相关活动入口。

孩子可见课件只放：

- 故事。
- 画面。
- 样片。
- 任务入口。
- 互动结果。
- 作品展示。

### 6.3 学生端

需要：

- 当前任务标题。
- 当前任务所需输入。
- 上传、填写、选择、语音、链接等任务控件。
- 提交按钮。
- 成功反馈。

不需要：

- 课程总目录。
- 教师预览链接。
- 大屏预览链接。
- 调试 API 地址。
- 后台状态。

### 6.4 大屏端

需要：

- 照片墙。
- 作品卡片。
- 全屏浏览。
- 展示顺序控制。

不需要：

- 后台状态。
- 处理队列。
- 授权细节。
- 技术错误详情。

### 6.5 家长可见展示页

需要：

- 三天课程成果。
- 小组项目卡片。
- 可体验产品链接。
- 结营展示内容。

不需要：

- 教师后台。
- 学生账号。
- 内部素材处理状态。

## 7. 数据对象

当前和近期需要稳定的数据对象：

- Camp：一期营。
- Student：学生。
- Team：小组。
- CourseModule：课程模块。
- LessonPage：课件页。
- Activity：课堂活动。
- TaskSubmission：学生任务提交。
- FuturePhotoSubmission：未来照相馆提交。
- MediaAsset：图片、生成图、展示素材。
- ShowcaseItem：作品展示卡片。
- AwardResult：奖项结果。

关键关系：

- 一个 Camp 有多个 Students、Teams、Modules。
- 一个 Module 有多个 LessonPages 和 Activities。
- 一个 Activity 可以产生多个 TaskSubmissions。
- 一个 Team 可以产生多个 ShowcaseItems。
- 一个 FuturePhotoSubmission 绑定一个 Student。
- 大屏和公开展示只读取允许展示的 ShowcaseItem 或 MediaAsset。

## 8. 未来照相馆验收清单

开营前必须逐项检查：

- 教师端可以进入未来照相馆模块。
- 封面标题简洁为“未来照相馆”。
- 样片可以完整查看，不被裁成窄条。
- 样片可以点击放大。
- 多张样片可以切换浏览。
- 学生端语音按钮提示为“说出你理想中的未来职业”。
- 学生端主问题为“你理想的未来职业是：”。
- 学生端主按钮为“提交”。
- PC 学生端显示扫码拍照二维码。
- 手机扫码后不需要登录。
- 手机扫码后可以打开相机或相册。
- 上传成功后 PC 学生端显示照片。
- 学生提交职业后，教师端能看到提交。
- 大屏只显示可展示结果。
- 孩子可见区域没有内部词。
- 生产环境完成同样检查。

## 9. 非目标

第一版不做：

- 完整报名线索管理。
- 多校区复杂权限系统。
- 成人商业训练营式 CRM。
- 本地大模型或本地图像生成。
- 面向学生的课程后台。
- 助教独立端。
- 把所有 AI 产品形态限制为网页、聊天机器人或故事生成器。

## 10. 下一步建议

推荐推进顺序：

1. 稳定未来照相馆 P0。
2. 拆分教师端、学生端、大屏端核心代码，降低后续改动风险。
3. 沿 D1 / D2 / D3 补齐每个关键环节的学生任务。
4. 建立小组项目空间和产品卡片展示区。
5. 建立结营作品展和家长可见成果页。
6. 固化部署检查、CDN 刷新和生产冒烟测试流程。

最近一轮开发建议：

- 先做“产品卡片展示区”数据流：团队提交链接，教师确认展示，大屏和家长页可点击体验。
- 同时继续压测未来照相馆的手机扫码上传和大屏展示。

## 11. 文案自检规则

每次改课件、学生端、大屏或公开展示页后，必须做孩子可见文案检查。

检查范围：

- PPT 画布。
- 全屏演示。
- 学生当前任务。
- 学生提交反馈。
- 大屏照片墙。
- 官网公开作品区。

至少检查以下词是否误入孩子可见区域：

- 后台
- 审核
- 待审核
- 管理配置
- 生成队列
- 发布状态
- 接口
- API
- 权限
- 数据库
- 同步
- 日志
- 运营

如果这些词出现在教师控制区，可以保留；如果出现在孩子可见区域，必须改写。

## 12. 当前决策

本 PRD 建议当前系统优先走“开营 MVP”路线。

判断标准：

- 不是先做大而全后台。
- 不是先做官网包装。
- 不是先扩展多角色。
- 先保证三天课能顺利带完。
- 先保证孩子能提交作品。
- 先保证作品能被安全地展示出来。
